# Confirmación de grupos por evento

La muestra en `dist/rsvp/` funciona desconectada. La versión para recibir respuestas se abre desde la invitación pero se ejecuta en el proyecto privado de la pareja. No hace envíos de correo, no registra información en el navegador y no sustituye un formulario existente. Un pase autoriza únicamente las plazas de ese grupo en ese evento.

## Preparar un evento nuevo

1. Ensayar primero con datos ficticios en **una planilla privada por evento**. Usar inicialmente un registro vacío de asistentes. La pestaña `Invitados` lleva en la fila 1 los encabezados `ID`, `Nombre`, `Grupo`, `Asistencia`, `Modalidad RSVP`, `Menor`, `Edad al evento`, `Recibo RSVP`. Pueden estar en cualquier orden y coexistir con las columnas del salón. No usar este modo de alta sobre un padrón ya cargado sin conciliarlo primero: el servicio no intenta identificar personas por el nombre ni reemplaza filas.
2. Crear la pestaña privada `Pases RSVP`, con las columnas **Código | Grupo | Cupo** en A:C. Una fila por invitación, con un ID de grupo único (letras sin acentos, números, guion o guion bajo). Dejar Código vacío para generarlo, y fijar Cupo entre 1 y 20 o dejarlo vacío para 10. Emitir pases solo para plazas ya aprobadas: no se aceptan asistentes extra por encima del cupo autorizado.
3. Preparar los cuatro archivos locales ejecutando `node tools/rsvp/build.cjs <carpeta-nueva>`. El paquete no contiene pases, IDs de planilla ni una lista de invitados. Copiar `Index.html`, `Modelo.gs`, `Code.gs` y `appsscript.json` a **un proyecto de Apps Script distinto por evento**, nunca al proyecto de solo lectura del contador. Configurar en propiedades del script `KAZA_REGISTRO_ID` con el ID de ese registro privado. Se usa el servicio avanzado de Sheets; con un proyecto estándar de Google Cloud, habilitar también la API de Sheets. Dar a la cuenta operadora acceso solo a los archivos que deba administrar.
4. Desde el editor privado de Apps Script, ejecutar **completarCodigos_** después de preparar/congelar esas filas. Solo llena códigos vacíos, no reemplaza códigos entregados. Entregar cada código en privado al grupo correspondiente, por separado del enlace. No incluir códigos, nombres, claves ni edades en una URL.
5. Solo con autorización del evento, [desplegar la aplicación web de Google](https://developers.google.com/apps-script/guides/web) ejecutada como la cuenta operadora y con acceso al formulario sin iniciar sesión. La hoja sigue siendo privada. En el editor KAZA elegir **Confirmar → Formulario de KAZA** y pegar su URL de producción terminada en `/exec`. Nunca pegar la URL del contador, una URL `/dev` o un enlace de Sheets. Si el dominio no admite este flujo, mantener el formulario externo.
6. Desde una invitación descargada, probar en incógnito y en un teléfono con un grupo de prueba: un adulto, un menor y un bebé de 0 años. Comprobar las filas, el cupo y el contador en un registro de prueba; repetir el envío y simular una ausencia. No abrir inscripciones reales antes de esa revisión y de acordar el acceso y la conservación de los datos de menores.

## Qué queda registrado

- En una respuesta afirmativa se anota **solo a quienes van**: para una pareja es posible confirmar una sola persona seleccionando Individual. Familia o grupo admite desde 2 hasta el cupo concedido. Un pase de una sola plaza no ofrece las modalidades de grupo.
- Se escribe el grupo entero en una operación. El servidor vuelve a comprobar el pase, el cupo y las edades. Un reintento idéntico no duplica filas. Si ese grupo ya tenía registros o pide cambiar su respuesta, se deriva a la organización: el alta pública no sobrescribe ni elimina personas, mesas u otros datos. Las correcciones se gestionan en privado, preservando el historial del evento.
- El registro distingue edades válidas (incluido 0) de celdas vacías y permite filtrar por asistencia y minoría de edad. El personal del salón no necesita los códigos ni la columna de recibos. Un filtro de una planilla compartida **no** limita lo que la otra persona puede leer.
- El [contador de confirmados](../../REGISTRO-MAESTRO.md#contador-público-de-confirmados) puede apuntar a la misma planilla con su **propio** proyecto de solo lectura. No devuelve edades, grupos ni nombres. La [comunicación del formulario con el servidor](https://developers.google.com/apps-script/guides/html/communication) se realiza dentro de la aplicación del evento.
